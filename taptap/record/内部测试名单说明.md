# 内部测试名单模板（TapTap · 内部测试 ≤100 人）

用途：TapTap 后台「版本发布 → 测试 → 内部测试 → 添加测试用户 → 导入用户表格」。
新用户会收到站内信，在 TapTap 启动器/网页里看到「参与测试」并下载。

## 怎么拿到 TapTap ID

| 场景 | 方法 |
| --- | --- |
| 对方自己在用 TapTap | 打开 App → 我的 → 点头像进个人主页 → 主页链接里的那串数字就是 ID，让他截图或复制给你 |
| 你手上有对方的昵称 | 在 TapTap 站内搜昵称，进主页复制主页链接，末尾数字即 ID |
| 批量收集 | 发一个表单（问卷/腾讯文档），字段只要「TapTap ID + 昵称」，别收手机号（没必要也不合规） |

> ID 是纯数字（如 `12345678`），**不要填昵称**，后台只认 ID。

## 表格怎么填

直接用同目录的 `internal-test-users.csv`，用 Excel / WPS 打开，按批次填：

| 列 | 说明 |
| --- | --- |
| `taptap_id` | 纯数字，必填 |
| `nickname` | 方便你自己认人，后台会忽略 |
| `batch` | 批次（建议按「自己 → 朋友 → 社群」分三批，出问题好定位） |
| `platform` | 固定填 `PC` |
| `note` | 备注（例如「已确认会玩」「B 站粉丝」） |
| `invited_at` | 你发邀请的日期，填 `YYYY-MM-DD` |

**导入前自查**：

1. 去掉表头行（后台要的是纯数据行，具体看导入向导提示）
2. 去重：同一个 ID 只留一行
3. ID 列不能有空格、不能有字母
4. 单次导入不要超过 100 行（内部测试全员上限 100）

## 批次建议

| 批次 | 人数 | 目的 |
| --- | --- | --- |
| 批次 1：自己 | 1–3 | 自己装一遍，验证包能下、能启动、存档正常 |
| 批次 2：熟人 | 5–10 | 抓「第一次玩会不会卡住」，重点问教程够不够 |
| 批次 3：社群 | ≤100 总量 | 有真实反馈后再扩大，避免第一批就口碑崩 |

## 邀请文案（直接复制发出去）

```
《零日值班》内部测试，就 10 个名额，先到先得。

玩法：你是深夜的安全值班员，10 个小时里要掐断 6 条攻击链，同时别把公司业务关停。
四步走完才算解决：调查 → 控制 → 清除 → 恢复。

需要的准备：
1. 电脑装 TapTap 启动器（或直接用网页版 taptap.cn）
2. 把你的 TapTap ID 发我（个人主页链接末尾那串数字）
3. 收到站内信后就能下载，Windows 10/11 都能跑，不用装 Python

反馈三件事就行：卡在哪一步、哪句话没看懂、想不想再玩一局。
```

## 测试期注意

- 游戏状态保持「敬请期待 / 预约」，**别点「正式上线」**（点了就是首发状态）
- 内部测试最多 100 人，超出要另开计划
- 测试结束后删掉名单，别长期留着别人的 ID
- 收到反馈记得回，TapTap 的社区评分对后上线影响很大
