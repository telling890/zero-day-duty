# 实机录屏分镜（40 秒）

> TapTap 对「实机录屏」的硬规则（摘自官方物料要求）：
> - MP4 / MOV，H.264 或 HEVC，长度 >15 秒（建议 2 分钟内），短边 ≥540px
> - **前 5 秒必须出现核心玩法**，且核心玩法要**连续演示超过 10 秒**
> - 不要从头录、不要 CG/过场/立绘占大段，**别做前贴片**
> - **不加配音、不加字幕**，不许画中画，录屏内容占比 >80%
> - 不许出现其他平台 Logo/水印、折扣充值画面、遮挡（圣光/马赛克）

这个分镜就是按这些规则倒推的：**一开场就是处置动作，全片只做「演示玩法」这一件事**。

---

## 一、录制前准备（5 分钟）

| 项目 | 设置 |
| --- | --- |
| 游戏启动 | `零日值班.exe --seed 2024 --difficulty standard`（固定种子，方便重录同一局） |
| 窗口 | 1280×720 固定窗口，放在屏幕中央 |
| 录制工具 | OBS「窗口捕获」只抓游戏窗口，**不抓任务栏**；60fps；H.264；CQP 20 左右 |
| 桌面清理 | 关掉微信/QQ/邮件通知；隐藏桌面图标；关闭输入法候选框 |
| 鼠标 | 录制时移动放慢，点击后停 0.5 秒再动（观众才看得清） |
| 音轨 | **可留游戏音效、绝不解说**（TapTap 不允许配音；音效是程序合成的，无版权风险） |

> 录 3 分钟，剪出 40 秒。别一次成型，分 5 段录更容易卡点。

## 二、分镜表

### 00:00–00:05　开场即核心玩法（最关键）

| 画面 | 操作 |
| --- | --- |
| 已经在「值班中」界面，顶部指标可见 | 提前点掉简报，停在主界面，直接开始录 |
| 点右侧第一条告警「可疑邮件：伪造付款通知」 | 鼠标慢移，点一下，停 0.5 秒 |
| 操作面板出现「调查告警」按钮 | 让按钮出现即可，**不要马上点** |

> 这 5 秒要让观众看到：有告警列表、有网络拓扑、有操作面板——一眼知道是「安全值班」题材。

### 00:05–00:15　调查 + 控制（连续演示 ≥10 秒）

| 时间 | 画面 | 操作 |
| --- | --- | --- |
| 5–8s | 点「调查告警」（1 AP / ¥20） | 点击 → 停住，展示出现的真实等级、线索、**下一跳** |
| 8–11s | 鼠标划过「下一跳」那句提示 | 只移动不点击，让文字停 2 秒 |
| 11–15s | 按 `` ` `` 打开终端 | 命令窗弹出，敲 `isolate PC-01` → 回车 |

> 这段是「核心玩法连续展示」的主体：调查 → 判断 → 控制。终端那一下是**差异化卖点**，必须留在前 15 秒内。

### 00:15–00:25　清除 + 恢复（把四步走完）

| 时间 | 画面 | 操作 |
| --- | --- | --- |
| 15–19s | Esc 关终端，点「清除威胁」（2 AP / ¥60） | 点击后停住，看告警变「已清除」 |
| 19–23s | 点「解除隔离」（1 AP） | 展示设备重新上线、业务恢复 |
| 23–25s | 顶部指标变化（安全度↑、可用性↑） | 鼠标轻扫指标区 |

> 这一段承担「顺序不能错」的教学表达——观众看到四步走完，就懂这游戏在玩什么。

### 00:25–00:33　第二种玩法：脚本（差异化的第二枪）

| 时间 | 画面 | 操作 |
| --- | --- | --- |
| 25–27s | 按 `C` 打开自动化剧本 | 面板弹出 |
| 27–30s | 下拉选模板「自动巡检（推荐）」 | 选模板 → 代码出现 |
| 30–33s | 点「▶ 运行」，看逐条输出 | 输出区滚动 `✓ 调查 / ✓ 清除` |

> 这一段是给「这游戏不只是点点点」的证据。3 秒够了，别拖。

### 00:33–00:40　收尾：结算与复盘

| 时间 | 画面 | 操作 |
| --- | --- | --- |
| 33–36s | 点「推进回合」，推进两三次 | 看时间从 22:00 → 01:00 |
| 36–40s | 直接跳到结算（可按 Esc 退出或打完剩余回合） | 停在「结算时间线」上，让分数和「最大失误」停在画面里 2 秒 |

> 结尾不要放 Logo 贴片（TapTap 不许除厂商/游戏 Logo 外的后贴片），停在结算画面最自然。

## 三、剪辑要点

1. **剪掉所有空转**：等待、鼠标找不到按钮、读教程的时间全部剪掉
2. 保留真实的 0.5 秒停顿（观众需要时间看清），但不要长于 1.5 秒
3. 不要加速到失真：最多 1.2×，否则「回合制」的节奏感会丢
4. 导出：1920×1080 / 60fps / H.264 / 8–15 Mbps，文件控制在 200 MB 内（TapTap 上限 5 GB，但小一点加载快）
5. 自检：导出后**关掉音量看一遍**——没有字幕、没有配音、全靠画面是否讲得通？讲得通就合格

## 四、三条最容易被打回的坑

| 坑 | 正确做法 |
| --- | --- |
| 开头放了 3 秒游戏 Logo 动画 | 直接删，第一帧就要是玩法画面 |
| 加了「10 回合策略游戏」之类的字幕 | 全部删掉，TapTap 明确不许字幕 |
| 录到了任务栏 / 桌面 / 微信弹窗 | 重录，用 OBS 窗口捕获只抓游戏窗口 |

## 五、录完检查清单

- [ ] 时长 >15 秒（建议 40 秒左右）
- [ ] 前 5 秒内出现核心玩法，且玩法连续 ≥10 秒
- [ ] 无配音、无字幕、无前贴片/后贴片
- [ ] 无其他平台 Logo/水印、无折扣充值画面
- [ ] 全屏游戏画面，无画中画、无遮挡
- [ ] MP4/MOV + H.264/HEVC，短边 ≥540px
- [ ] 文件放 `taptap/record/`（脚本自检会认这个目录）
